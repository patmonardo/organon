## Wrapping Lattice

### 1. DataFrame Wrapping (execution wrapping)

Role:

- preserves high-performance tabular execution
- provides immediate runtime body for mediated semantics

Boundary:

- no semantic sovereignty claims
- no model-level feature authority

Primary forms:

- expression wrapping
- lazy/eager plan wrapping
- deterministic execution receipts

### 2. Dataset Wrapping (semantic wrapping)

Role:

- names and commits semantic intent
- materializes artifact, provenance, and compilation visibility

Boundary:

- does not erase DataFrame runtime reality
- does not pretend algorithm outcomes are self-grounding truth

Primary forms:

- Model:Feature::Plan mediation
- artifact profile commitments
- compilation graph commitments

### 3. GraphStore Wrapping (service wrapping)

Role:

- mediates graph operations through stable service contracts
- keeps graph operations provenance-legible in Dataset terms

Boundary:

- GraphStore scale does not become semantic authority
- storage API does not bypass Dataset and Shell governance

Primary forms:

- graph operation contract wrapping
- graph artifact emission wrapping
- request/receipt trace wrapping

### 4. Algorithm Wrapping (procedure/algorithm wrapping)

Role:

- binds algorithm execution to explicit public procedure routes
- keeps storage/computation internals insulated from public surface

Boundary:

- procedures stay thin and routing-centric
- algorithm modules stay deep and explicit

Primary forms:

- mode and capability wrapping
- termination and progress wrapping
- result-shape and error-class wrapping

### 5. ML Pipeline Wrapping (learning wrapping)

Role:

- allows heavy GML/GNN/LM delivery without surrendering metapipeline authority
- keeps learning outputs mapped back to semantic commitments

Boundary:

- magnitude and optimization do not displace rationale
- external learners remain consumers/emitters of Dataset-governed artifacts

Primary forms:

- learning lifecycle wrapping
- evaluation and report wrapping
- semantic trace-back wrapping

## GraphFrame Position in the Lattice

GraphFrame is where all five wrappings become jointly operational for graph work:

- DataFrame wrapping supplies execution substrate
- Dataset wrapping supplies semantic commitments
- GraphStore wrapping supplies service contracts
- Algorithm wrapping supplies controlled execution semantics
- ML wrapping supplies scalable learning surfaces

GraphFrame is therefore an integrative intelligence API, not a new isolated runtime.

## Promotion Gates for Any New Wrapper

1. Grounding gate

- Explicitly map to <Frame,Series,Expr><Model,Feature,Plan><Corpus,LM,Logic>.

2. Interface gate

- Declare which existing artifact/service surfaces are enriched.

3. Trace gate

- Prove provenance continuity from source commitment to emitted result.

4. Regression gate

- Demonstrate no empirical adequacy regressions on baseline runs.

5. Rationale gate

- Show conceptual reason the wrapper is needed, not only implementation convenience.

## Failure Modes to Prevent

1. Wrapper inflation

- adding wrappers that do not add determinate mediation value.

2. Scope collapse

- collapsing graph-scope commitments into node/edge-only summaries.

3. Procedure thickening

- leaking intelligence into procedure routes that should remain thin.

4. Optimization reductionism

- substituting benchmark gains for rationale coherence.

5. Provenance amnesia

- losing feature/plan trace during algorithm and ML projection stages.
